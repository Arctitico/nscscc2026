假设顺序单发射。有以下指令流：
```
a
b
c
```
其中，b要用到a的结果。

根据 coissue.md 中的定义，分类讨论：

## 1：a 是 N 类指令
那么 a 在 EX1 即可得到结果，可以立马前递到 RF.
| 周期 | RF | EX1 | EX2 | CM |
|------|----|-----|-----|----|
| 1    | a  |     |     |    |
| 2    | b  | a   |     |    |
| 3    | c  | b   | a   |    |
| 4    |    | c   | b   | a  |

## 2: a 是 MU 类指令
那么 a 一定是 mul，会在 EX1 发起乘法请求，在下一周期于 EX2 得到乘法结果，此时才可以前递到RF。
也就是说，b 必须要等 a 进入 EX2 才能拿前递交结果，要多等一拍。

| 周期 | RF | EX1 | EX2 | CM |
|------|----|-----|-----|----|
| 1    | a  |     |     |    |
| 2    | b  | a   |     |    |
| 3    | b  |     | a   |    |
| 4    | c  | b   |     | a  |

如果 b 是 N 类指令，那么我们可以做晚前递：允许 b 在周期 2 末携带“操作数等待 MUL 结果”的标记提前进入 EX1。周期 3 内，a 的 EX2 乘积经晚旁路直接进入 b 的 ALU，并在周期 3 末把 b 送入 EX2。

即，加一条 MUL -> ALU 的前递。可以做到如下表所示：

| 周期 | RF | EX1 | EX2 | CM |
|------|----|-----|-----|----|
| 1    | a  |     |     |    |
| 2    | b  | a   |     |    |
| 3    | c  | b   | a   |    |
| 4    |    | c   | b   | a  |

不过 MUL -> ALU 前递会导致时序急剧恶化，因此不实现。

## 3： a 是 ME 类指令
那么 a 一定是 ld （因为 st 不会写寄存器），会在 EX1 发起访存请求。下一周期，a 会在 EX2，如果 dcache命中的话当拍即可得到结果，否则要一直等到访存完成才能前递到RF。
也就是说，b 必须要等 a 进入 EX2 并且访存完成才能拿前递交结果。

| 周期 | RF | EX1 | EX2 | CM |
|------|----|-----|-----|----|
| 1    | a  |     |     |    |
| 2    | b  | a   |     |    |
| 3    | b  |     | a   |    |
| 4    | b  |     | a   |    |
| ...  | b  |     | a   |    |
| x-1  | b  |     | a   |    |
| x    | c  | b   |     | a  |

上例中，x-1 周期 a 访存完成，前递到了 RF，所以在 x 周期 b 进入 EX1.

x=4 ，说明 a 访存命中 dcache，此时情况与 a 是 MU 类指令的情况相同，多等一拍。

x=4，如果 b 是 store 指令，且 b 依赖的 a 的结果是 b 的 store 内容而不是 store 地址，那么可以加一条晚前递：

```
load结果（EX2）
→ store-data late mux / st_wdata（EX1）
→ D-cache cpu_wdata 请求捕获
```

可以做到如下表所示：

| 周期 | RF | EX1 | EX2 |
|------|----|-----|-----|
| 1    | a  |     |     |
| 2    | b  | a   |     |
| 3    | c  | b   | a   |

允许 b 在周期 2 末携带“store data 等待 load 结果”的标记进入 EX1，在周期 3 即可发起请求。

## 4：a 是 B 类指令

普通 b/beq/bne 不写通用寄存器，因此不存在 b 使用 a 写回结果的数据相关，只有控制相关，由分支预测和 flush 处理。

bl 和 jirl 会写入链接地址 PC+4。该结果在 EX1 已经得到，可以直接前递到RF，因此其数据相关行为与 N 类指令相同，不产生额外气泡。

## 5：a 是 S 类指令

当前 S 类只有 cpucfg。cpucfg 的结果在 EX1 中产生，可以直接前递到 RF，因此其数据相关行为与 N 类相同，不产生额外气泡。
