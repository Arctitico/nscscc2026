既然我们决定要做顺序双发射，那么哪两类指令可以共同发射就很重要了。
定义以下五类指令：
N：普通指令，包括使用到ALU的运算指令之类的。
MU：乘法指令。
B：分支指令。
ME：访存指令。
S：特殊指令，永远单发射。好像只有cpucfg，因为我们声称cache不存在。

我们有一个乘法器，一个LSU（好像），两套ALU.

| slot0/slot1 | N | MU | B | ME | S |
|-------------|---|----|---|----|---|
| N           | y | y  | 1 | y  | n |
| MU          | y | n  | 13| 3  | n |
| B           | 2 | 23 | n | n  | n |
| ME          | y | 3  | 1 | n  | n |
| S           | n | n  | n | n  | n |

slot0 是较老的指令，slot1 是较新的指令。也就是说如果是顺序单发射，先执行的是slot0的指令，后执行的是slot1的指令。
在设计上，slot0和slot1是紧密相连的，pc的delta仅为4. 

y：支持。
n：不支持。
1：需要处理slot1分支解析的问题
2：slot0 分支误预测才杀 slot1
3：两个长延迟/握手型单元可能在不同拍完成，需要保存先完成的一侧

在模块的设计上，应该首先保障可读性。
在IS的判断逻辑中，应该分s0和s1来判断，可以用布尔代数化简的方法来简化逻辑；在EX是否ready_go（也就是两个s有没有都执行完）的判断中，应该有s0_ready_go和s1_ready_go两个信号来判断，然后ready_go = s0_ready_go && s1_ready_go。记得判断slot1是不是valid。通过这种方式可以提高N与MU和ME的并发。当然这两个ready_go信号可能会在不同拍完成，因此需要寄存器保存先完成的一侧的ready_go信号。
